2. FLUJO DE NEGOCIO DEFINIDO
==================================================

Flujo directo a gerencia:

- Disco duro
- Cable de poder
- Ruedas o base
- Accesorios simples
- Otros artículos definidos como aprobación directa

Flujo con revisión del jefe de área:

- Tapas
- Paneles
- Unidades completas
- Subpartes
- Componentes técnicos
- Piezas que podrían retirarse de otra máquina

El jefe de área debe evaluar:

- Stock de componentes
- Almacén de alquiler
- Máquina para partes
- Máquina con problemas
- Máquina operativa
- Compra externa
- Reparación externa
- Sin disponibilidad

Después:

- Gerencia aprueba, aprueba parcialmente, rechaza o solicita información.
- Se reserva o selecciona el origen.
- Se autoriza retiro cuando corresponde.
- Logística prepara y entrega.
- El técnico confirma recepción.
- Luego se instala, devuelve o repone según el caso.

9. RELACIONES IMPORTANTES
==================================================

RepairPartRequest:

- Pertenece a Repair.
- Tiene muchos RepairPartRequestItem.
- Conserva estado general, prioridad y área responsable.
- Registra solicitante, aprobación, rechazo y cierre.

RepairPartRequestItem:

- Pertenece a una solicitud.
- Puede vincularse a RepairChecklistItem.
- Puede vincularse a EquipmentComponent.
- Puede usar ComponentInventory.
- Puede seleccionar Equipment como máquina donante.
- Puede seleccionar RentalEquipment cuando el equipo pertenece al módulo alquileres.
- Cada ítem puede tener flujo y origen independiente.

RepairPartSource:

- Define de dónde se obtiene la parte.
- Puede usar stock, almacén, equipo donante, compra o reparación externa.

RepairPartWithdrawal:

- Controla autorización y retiro físico desde una máquina o almacén.

RepairPartDelivery:

- Controla preparación, entrega y confirmación de recepción.

RepairPartReplacement:

- Controla devolución, reposición, préstamo temporal o reparación externa.

11. INTEGRACIÓN PENDIENTE CON REPAIRCOMPONENT
==================================================

RepairComponent sigue manejando el ciclo físico del componente:

- solicitado
- reservado
- entregado
- instalado
- retirado
- devuelto
- consumido
- descartado

La nueva solicitud administrativa debe conectarse a RepairComponent.

Regla propuesta:

Cuando un RepairPartRequestItem llegue a RECEIVED:

- Crear o vincular un RepairComponent.
- Asignar repair.
- Asignar component.
- Asignar inventory cuando exista.
- Registrar cantidad entregada.
- Mantener referencia al ítem de solicitud.

No modificar RepairComponent hasta revisar su archivo completo y decidir el campo exacto de relación.

==================================================
12. INTEGRACIÓN PENDIENTE CON CHECKLIST
==================================================

Cuando un RepairChecklistItem tenga:

- requiere cambio
- subcomponentes seleccionados
- cantidades

Debe poder generar RepairPartRequestItem.

La solicitud debe conservar:

- checklist_item
- component
- cantidad
- motivo técnico
- origen checklist
- técnico solicitante

No modificar repair_checklist.py hasta revisar la lógica completa actual.
